<div class="exam-q-scenario">

**A company hosted a web application in an Auto Scaling group of EC2 instances. The IT manager is concerned about the over-provisioning of the resources that can cause higher operating costs. A Solutions Architect has been instructed to create a cost-effective solution without affecting the performance of the application.**

**Which dynamic scaling policy should be used to satisfy this requirement?**

</div>

<div class="exam-options-list">
  <div class="exam-option-item">**A)** Simple scaling policy</div>
  <div class="exam-option-item">**B)** Step scaling policy</div>
  <div class="exam-option-item">**C)** Target tracking scaling policy</div>
  <div class="exam-option-item">**D)** Scheduled scaling policy</div>
</div>

<details class="exam-answer-details">
<summary class="exam-summary-btn">
  <span>💡 Click to Reveal Answer & In-Depth Burmese Explanation (အဖြေနှင့် ရှင်းလင်းချက် ကြည့်ရန်)</span>
  <span>▼</span>
</summary>
<div class="exam-answer-body">

**✅ Correct Answer: C**

### မြန်မာဘာသာ အသေးစိတ် ရှင်းလင်းချက်

**C) Target tracking scaling policy → ✅ မှန်ပါသည်**
> **Target tracking scaling policy** သည် သတ်မှတ်ထားသော metric (ဥပမာ: Average CPU Utilization 50%, ALB Request Count Per Target 1000) ကို Target Value အဖြစ် သတ်မှတ်ပေးထားရုံဖြင့် Auto Scaling Group (ASG) က ထို metric ပတ်လည်တွင် ရှိနေစေရန် instances များကို အလိုအလျောက် တိုးခြင်း/လျှော့ခြင်း (scale out / scale in) ပြုလုပ်ပေးပါသည်။ ၎င်းသည် resource over-provisioning (အရင်းအမြစ် ပိုလျှံစွာ သုံးစွဲမိခြင်းကြောင့် ကုန်ကျစရိတ် မြင့်တက်ခြင်း) ကို ကာကွယ်ပေးပြီး cost-effective အဖြစ်ဆုံး dynamic scaling policy ဖြစ်ပါသည်။

**A) Simple scaling policy → ❌ မှားပါသည်**
> Simple scaling သည် CloudWatch alarm တစ်ခု breach ဖြစ်ပါက instance ပမာဏ သတ်မှတ်ထားသလောက် (ဥပမာ +1 instance) တိုးပေးပြီး cooldown period ကို စောင့်ရပါသည်။ Traffic အတက်အကျ မြန်ဆန်ပါက over-provisioning သို့မဟုတ် under-provisioning ဖြစ်လွယ်ပြီး cost-effective မဖြစ်ပါ။

**B) Step scaling policy → ❌ မှားပါသည်**
> Step scaling သည် metric ၏ alarm breach ပမာဏအလိုက် အဆင့်ဆင့် (steps) တိုးပေးနိုင်သော်လည်း (ဥပမာ CPU 60% တွင် +1, 80% တွင် +3)၊ Target metric value တစ်ခုတည်းကို အတိအကျ ထိန်းသိမ်းရန် manual configuration များစွာ လိုအပ်ပြီး over-provisioning ကို target tracking လောက် တိကျစွာ မထိန်းနိုင်ပါ။

**D) Scheduled scaling policy → ❌ မှားပါသည်**
> Scheduled scaling သည် နေ့ရက်၊ အချိန် (time-based schedule) အလိုက်သာ scale လုပ်ခြင်းဖြစ်ပြီး "Dynamic Scaling Policy" မဟုတ်ပါ။ မမျှော်လင့်ထားသော traffic အပြောင်းအလဲများကို မလိုက်လျောညီထွေ မလုပ်ဆောင်နိုင်ပါ။

**💡 Real Exam Tip:**
- **"Cost-effective + Prevent over-provisioning + Keep metric at a target value"** → **Target tracking scaling policy**

<div class="exam-q-scenario">

**A travel photo-sharing website is using Amazon S3 to serve high-quality photos to visitors. After a few days, it was discovered that other travel websites are linking to and using these photos. This has resulted in financial losses for the business. The team initially applied PutBucketPolicy with referrer restrictions, but found that referrer headers can be spoofed, rendering this approach insufficient.**

**What is the MOST effective method to mitigate this issue?**

</div>

<div class="exam-options-list">
  <div class="exam-option-item">**A)** Configure an Amazon CloudFront distribution and serve the photos using CloudFront signed URLs or signed cookies, with Origin Access Control (OAC) to restrict direct S3 access</div>
  <div class="exam-option-item">**B)** Implement AWS WAF on the S3 bucket to inspect and block unauthorized HTTP Referer headers</div>
  <div class="exam-option-item">**C)** Enable S3 Object Lock in Governance Mode on all image objects in the bucket</div>
  <div class="exam-option-item">**D)** Configure Cross-Origin Resource Sharing (CORS) on the S3 bucket to allow only the company's domain</div>
</div>

<details class="exam-answer-details">
<summary class="exam-summary-btn">
  <span>💡 Click to Reveal Answer & In-Depth Burmese Explanation (အဖြေနှင့် ရှင်းလင်းချက် ကြည့်ရန်)</span>
  <span>▼</span>
</summary>
<div class="exam-answer-body">

**✅ Correct Answer: A**

### မြန်မာဘာသာ အသေးစိတ် ရှင်းလင်းချက်

**A) Configure an Amazon CloudFront distribution with signed URLs / signed cookies + OAC → ✅ မှန်ပါသည်**
> အခြား website များက မိမိ S3 bucket ထဲရှိ ဓာတ်ပုံများကို တိုက်ရိုက် link ချိတ်သုံးခြင်း (Hotlinking / Leeching) ကို ကာကွယ်ရန် အထိရောက်ဆုံး နည်းလမ်းမှာ **Amazon CloudFront** ကို အရှေ့တွင် ခံပြီး **Signed URLs** သို့မဟုတ် **Signed Cookies** ဖြင့်သာ access ပေးခြင်း ဖြစ်ပါသည်။ ထို့အပြင် S3 bucket သို့ direct access ကို ပိတ်ပြီး **Origin Access Control (OAC)** ဖြင့် CloudFront မှသာ လာခွင့်ပြုထားသောကြောင့် Referer header spoofing ပြုလုပ်၍ မရတော့ဘဲ ခွင့်ပြုချက်ရှိသူ (authen ဖြစ်ပြီးသူ) သာ ဓာတ်ပုံများကို ကြည့်ရှုနိုင်မည် ဖြစ်ပါသည်။

**B) Implement AWS WAF on the S3 bucket → ❌ မှားပါသည်**
> AWS WAF ကို Amazon S3 bucket သို့ တိုက်ရိုက် ချိတ်ဆက်၍ မရပါ။ AWS WAF ကို CloudFront, ALB, API Gateway သို့မဟုတ် App Runner အရှေ့တွင်သာ တပ်ဆင်နိုင်ပါသည်။

**C) Enable S3 Object Lock → ❌ မှားပါသည်**
> S3 Object Lock သည် objects များ မတော်တဆ ဖျက်ဆီးခံရခြင်း သို့မဟုတ် overwrite လုပ်ခံရခြင်းမှ WORM (Write Once Read Many) စနစ်ဖြင့် ကာကွယ်ခြင်းဖြစ်ပြီး hotlinking ကာကွယ်ခြင်းနှင့် မသက်ဆိုင်ပါ။

**D) Configure CORS on the S3 bucket → ❌ မှားပါသည်**
> CORS သည် web browser ၏ JavaScript (AJAX/Fetch) မှ cross-origin request များကိုသာ စစ်ဆေးခြင်းဖြစ်ပါသည်။ `<img>` tag ဖြင့် တိုက်ရိုက် hotlink လုပ်ခြင်း သို့မဟုတ် curl ဖြင့် ဆွဲယူခြင်းကို CORS က တားဆီးနိုင်စွမ်း မရှိပါ။

**💡 Real Exam Tip:**
- **"Prevent Hotlinking / Prevent unauthorized access to private media files"** → **CloudFront + Signed URLs / Signed Cookies + OAC**

<div class="exam-q-scenario">

**A company wishes to query data that resides in multiple AWS accounts from a central data lake. Each account has its own Amazon S3 bucket that stores data unique to its business function. Access to the data lake must be granted based on user roles.**

**Which solution will minimize overhead and costs while meeting the required access patterns?**

</div>

<div class="exam-options-list">
  <div class="exam-option-item">**A)** Replicate all S3 data from each account into a single central S3 bucket using S3 Cross-Region Replication (CRR) and query using Amazon EMR</div>
  <div class="exam-option-item">**B)** Use AWS Lake Formation to manage cross-account permissions and use Amazon Athena to query the data in place</div>
  <div class="exam-option-item">**C)** Set up an Amazon Redshift cluster in the central account and load data using AWS Glue ETL daily</div>
  <div class="exam-option-item">**D)** Configure VPC Peering between all accounts and deploy an Amazon OpenSearch cluster to index all S3 buckets</div>
</div>

<details class="exam-answer-details">
<summary class="exam-summary-btn">
  <span>💡 Click to Reveal Answer & In-Depth Burmese Explanation (အဖြေနှင့် ရှင်းလင်းချက် ကြည့်ရန်)</span>
  <span>▼</span>
</summary>
<div class="exam-answer-body">

**✅ Correct Answer: B**

### မြန်မာဘာသာ အသေးစိတ် ရှင်းလင်းချက်

**B) Use AWS Lake Formation + Amazon Athena → ✅ မှန်ပါသည်**
> **AWS Lake Formation** သည် multi-account architecture များတွင် S3 bucket များစွာရှိ data များကို central catalog တစ်ခုတည်းမှတစ်ဆင့် cross-account access ပေးနိုင်ပြီး၊ IAM role-based, table-level, column-level နှင့် row-level access control များကို ဗဟိုမှ အလွယ်တကူ စီမံခန့်ခွဲနိုင်ပါသည်။ ထို့အပြင် **Amazon Athena** သည် serverless interactive query service ဖြစ်သောကြောင့် server infrastructure run ထားစရာမလိုဘဲ query လုပ်သလောက် data scan ပေါ်တွင်သာ ကျသင့်သဖြင့် overhead နှင့် costs ကို အနည်းဆုံးဖြစ်စေပါသည်။

**A) Replicate all S3 data + Amazon EMR → ❌ မှားပါသည်**
> Data အားလုံးကို central S3 သို့ ထပ်မံ replicate လုပ်ခြင်းသည် storage cost နှင့် data transfer cost နှစ်ဆ ကုန်ကျစေပါသည်။ Amazon EMR cluster run ခြင်းသည် serverless မဟုတ်ဘဲ operational overhead အလွန်များပါသည်။

**C) Amazon Redshift cluster + AWS Glue ETL daily → ❌ မှားပါသည်**
> Redshift cluster ကို အမြဲတစေ run ထားရသဖြင့် ကုန်ကျစရိတ် ကြီးမြင့်ပြီး၊ Glue ETL ဖြင့် နေ့စဉ် data load လုပ်ရခြင်းသည် overhead များပြားစေပါသည်။

**D) VPC Peering + Amazon OpenSearch cluster → ❌ မှားပါသည်**

## Q65
**A tech company that you are working for has undertaken a Total Cost Of Ownership (TCO) analysis evaluating the use of Amazon S3 versus acquiring more storage hardware. The result was that all 1200 employees would be granted access to use Amazon S3 for the storage of their personal documents.**

**Which of the following will you need to consider so you can set up a solution that incorporates a single sign-on feature from your corporate AD or LDAP directory and also restricts access for each individual user to a designated user folder in an S3 bucket? (Select TWO.)**

- **A)** Configure identity federation using SAML 2.0 with corporate AD/LDAP and AWS STS to obtain temporary credentials
- **B)** Use IAM policy variables such as ${aws:username} in the S3 bucket/IAM policy to restrict access to each employee's personal folder (e.g. arn:aws:s3:::mybucket/home/${aws:username}/*)
- **C)** Create 1200 individual IAM users manually in the AWS console
- **D)** Create a separate S3 bucket for each of the 1200 employees
- **E)** Configure an AWS Direct Connect connection for each employee

---
**✅ Correct Answers: A, B**

### မြန်မာဘာသာ အသေးစိတ် ရှင်းလင်းချက်

**A & B) SAML 2.0 Federation + IAM Policy Variables (${aws:username}) → ✅ မှန်ပါသည်**
> 1. **Single Sign-On (SSO):** ဝန်ထမ်း ၁၂၀၀ အတွက် IAM user ၁၂၀၀ လိုက်ဆောက်စရာ မလိုဘဲ corporate AD/LDAP မှတစ်ဆင့် **SAML 2.0 Identity Federation** ချိတ်ဆက်ပြီး **AWS STS** မှ temporary credentials ရယူစေရပါမည် (Option A)။
> 2. **Designated User Folder Restriction:** S3 bucket တစ်ခုတည်းတွင် ဝန်ထမ်းတစ်ဦးချင်းစီအတွက် သီးခြား folder တစ်ခုစီသာ ဝင်ရောက်ခွင့်ရစေရန် **IAM Policy Variables (`${aws:username}` သို့မဟုတ် `${saml:sub}`)** ကို အသုံးပြုရပါမည်:
> ```json
> {
>   "Effect": "Allow",
>   "Action": "s3:*",
>   "Resource": "arn:aws:s3:::mycompany-bucket/home/${aws:username}/*"
> }
> ```
> ဤ policy တစ်ခုတည်းဖြင့် ဝန်ထမ်း ၁၂၀၀ လုံးသည် မိမိတို့၏ username folder သို့သာ အလိုအလျောက် သီးသန့် ဝင်ရောက်နိုင်မည် ဖြစ်ပါသည်။ (Option B)။
