## အခန်း (၅) — စနစ်စောင့်ကြည့်ခြင်းနှင့် လည်ပတ်ရေး (Logging, Monitoring, Backup, Audit)

Production စနစ်တစ်ခုကို တည်ဆောက်ရုံသာမက ၎င်းစနစ် အချိန်ပြည့် တည်ငြိမ်စွာ လည်ပတ်နေစေရန်၊ ပြဿနာတက်ပါက အမြန်ဆုံး ရှာဖွေသိရှိနိုင်ရန်နှင့် ဒေတာများ မပျောက်ပျက်စေရန် အထူးအရေးပါသော စနစ်လည်ပတ်ရေးမဏ္ဍိုင်ကြီး ၄ ခု ဖြစ်သည့် **Logging, Monitoring, Backup** နှင့် **Audit** တို့ကို အသေးစိတ် ရှင်းပြထားပါသည်။

---

## ၁။ Logging (မှတ်တမ်း ထိန်းသိမ်းခြင်း)

### (က) ဒါကဘာလဲ? (What is it?)
- **Logging** ဆိုသည်မှာ ကွန်ရက်၊ Operating System နှင့် Application များ အတွင်း ဖြစ်ပျက်သမျှသော ဖြစ်ရပ် (Events)၊ ချိတ်ဆက်မှု (Connections)၊ အမှားအယွင်း (Errors) နှင့် လုပ်ဆောင်ချက်များကို အချိန်မှတ်တမ်း (Timestamp) နှင့်တကွ အသေးစိတ် ရေးသားမှတ်တမ်းတင်ထားခြင်း ဖြစ်ပါသည်။

### (ခ) ဘာကြောင့် သုံးတာလဲ? (Why use it?)
- ဝဘ်ဆိုက်တွင် 500 Error တက်သွားသည့်အခါ မည်သည့်နေရာတွင် အမှားဖြစ်သွားသည်ကို သိရှိနိုင်ရန်။
- စနစ်အတွင်းသို့ မသင်္ကာဖွယ်ရာ IP မှ ဝင်ရောက်ရန် ကြိုးစားနေခြင်းကို ခြေရာခံနိုင်ရန်။
- Post-Mortem (障害報告書 - Incident Report) ရေးသားရာတွင် ခိုင်လုံသော သက်သေအထောက်အထား ရရှိရန်။

### (ဂ) Cloud တွင် ရှိရမည့် Log ၃ မျိုး
1. **Application Logs (Laravel / Node.js Logs):** App အတွင်း Logic Error များ၊ Exception များကို မှတ်တမ်းတင်သည်။ (`storage/logs/laravel.log`)
2. **Web Server Access & Error Logs (Nginx / Apache / ALB Logs):** မည်သည့် IP က မည်သည့် URL ကို HTTP Status မည်မျှဖြင့် တောင်းဆိုသွားသည်ကို မှတ်တမ်းတင်သည်။
3. **Network Flow Logs (AWS VPC Flow Logs):** IP အဆင့်တွင် မည်သည့် Packet ကို Allow လုပ်ခဲ့သည်၊ မည်သည့် Packet ကို Security Group က Reject လုပ်ခဲ့သည်ကို မှတ်တမ်းတင်သည်။

### (ဃ) AWS CloudWatch Logs တွင် အသုံးပြုပုံ
```bash
# CloudWatch Logs Insights ဖြင့် 5xx Error အများဆုံးဖြစ်စေသော URL များကို ရှာဖွေခြင်း
fields @timestamp, @message
| filter status >= 500
| stats count() by uri
| sort count() desc
| limit 20
```

## ၂။ Monitoring (စနစ်ကျန်းမာရေးကို စဉ်ဆက်မပြတ် စောင့်ကြည့်ခြင်း)

### (က) ဒါကဘာလဲ? (What is it?)
- **Monitoring** ဆိုသည်မှာ Server များ၊ Database များနှင့် Network ၏ ကိန်းဂဏန်းအချက်အလက်များ (Metrics - ဥပမာ CPU %, Memory %, Disk Space, Network Latency, Request Count) ကို အချိန်နှင့်တစ်ပြေးညီ စောင့်ကြည့်တိုင်းတာနေခြင်း ဖြစ်ပါသည်။

### (ခ) ဘာကြောင့် သုံးတာလဲ? (Why use it?)
- **Proactive Detection:** ဝဘ်ဆိုက်ကြီး လုံးဝ ပြုတ်မကျမီ CPU 85% ရောက်နေပြီဖြစ်ကြောင်း သို့မဟုတ် Disk Space 90% ပြည့်လုနီးပါး ဖြစ်နေပြီဖြစ်ကြောင်း ကြိုတင် သတိပေးချက် (Alert) ရယူနိုင်ရန်။
- **Auto Scaling:** Traffic များလာပါက Server အရေအတွက်ကို အလိုအလျောက် တိုးပေးနိုင်ရန် (Scale-out)။

### (ဂ) အရေးကြီးသော Metrics & Alert တပ်ဆင်ပုံ (CloudWatch Alarms)
```
[ EC2 / RDS / ALB ]
        │ (Metrics ပို့ဆောင်ခြင်း)
        ▼
[ AWS CloudWatch Metrics ]
        │ (သတ်မှတ်ချက် ကျော်လွန်ပါက ဥပမာ: CPU > 80% for 5 mins)
        ▼
[ CloudWatch Alarm (ALARM State) ]
        │
        ▼
[ Amazon SNS Topic ]
        │
   ┌────┴──────────────────────────┐
   ▼                               ▼
[ Slack Channel Notification ]   [ PagerDuty On-Call SMS ]
```

## ၃။ Backup (အရန်ဒေတာ သိမ်းဆည်းခြင်းနှင့် ဘေးအန္တရာယ် ပြန်လည်ကုစားခြင်း)

### (က) ဒါကဘာလဲ? (What is it?)
- **Backup** ဆိုသည်မှာ စက်ပျက်စီးခြင်း၊ Ransomware တိုက်ခိုက်ခံရခြင်း သို့မဟုတ် လူမှားယွင်းပြီး Data ဖျက်မိခြင်း (Human Error) ဖြစ်ပေါ်လာပါက မူလအခြေအနေသို့ အချိန်မရွေး ပြန်လည်ရယူနိုင်ရန် Data များကို သီးခြားနေရာတစ်ခုတွင် မိတ္တူကူးယူ သိမ်းဆည်းထားခြင်း ဖြစ်ပါသည်။

### (ခ) သိထားရမည့် စံနှုန်းနှစ်ခု (RPO နှင့် RTO)
- **RPO (Recovery Point Objective):** ဒေတာ မည်မျှ အချိန်အထိ ဆုံးရှုံးမှုကို လက်ခံနိုင်သနည်း (ဥပမာ- RPO = 1 နာရီ ဆိုပါက လွန်ခဲ့သော ၁ နာရီအထိ ဒေတာကို ပြန်ရနိုင်ရမည်)။
- **RTO (Recovery Time Objective):** စနစ်ပျက်စီးသွားပါက ပုံမှန် ပြန်လည်လည်ပတ်နိုင်ရန် အချိန်မည်မျှကြာ အချိန်ယူ ပြင်ဆင်နိုင်သနည်း (ဥပမာ- RTO = ၃၀ မိနစ်)။

### (ဂ) AWS တွင် Backup ပြုလုပ်ပုံများ
1. **RDS Automated Backups & PITR (Point-In-Time Recovery):**
   - RDS သည် ၅ မိနစ်တိုင်း Transaction Log များကို Backup ပြုလုပ်ပေးသဖြင့် လွန်ခဲ့သော မိနစ်ပိုင်းအလိုထိ အချိန်တိကျစွာ ပြန်လည်ရယူနိုင်ပါသည်။
2. **AWS Backup (Centralized Policy):**
   - EBS, RDS, S3, EFS အားလုံးကို တစ်နေရာတည်းမှ Cron Schedule ဖြင့် အလိုအလျောက် Snapshot ကူးပေးခြင်း။
3. **Cross-Region Backup (Tokyo → Osaka):**
   - သဘာဝဘေးအန္တရာယ် (ငလျင်) ကြောင့် Tokyo Region တစ်ခုလုံး ပျက်စီးသွားသော်လည်း Osaka Region တွင် သိမ်းထားသော Backup မှ ပြန်လည်ထူထောင်နိုင်ပါသည်။

## ၄။ Audit (လုပ်ဆောင်ချက်များအား စစ်ဆေးအတည်ပြုခြင်း)

### (က) ဒါကဘာလဲ? (What is it?)
- **Audit** ဆိုသည်မှာ စနစ်တစ်ခုအတွင်း **"မည်သူက (Who)"၊ "မည်သည့်အချိန်တွင် (When)"၊ "မည်သည့်နေရာမှ (Where - Source IP)"၊ "မည်သည့်အရာကို (What Action)"** ပြုလုပ်သွားသနည်း ဟူသော အချက်ကို စစ်ဆေးအတည်ပြုခြင်း ဖြစ်ပါသည်။
- Logging သည် System/App ဖြစ်ရပ်များကို မှတ်တမ်းတင်ခြင်းဖြစ်ပြီး၊ Audit သည် **လူသားများနှင့် စီမံခန့်ခွဲရေးဆိုင်ရာ API ခေါ်ဆိုမှုများ (Governance & Compliance)** ကို အဓိက စစ်ဆေးခြင်း ဖြစ်ပါသည်။

### (ခ) ဘာကြောင့် သုံးတာလဲ? (Why use it?)
1. **လုံခြုံရေး စုံစမ်းစစ်ဆေးခြင်း (Security Forensics):** Database ပျက်သွားပါက မည်သည့် Engineer သို့မဟုတ် မည်သည့် Access Key က `DeleteDBInstance` API ကို လှမ်းခေါ်ခဲ့သနည်းကို ရှာဖွေနိုင်ရန်။
2. **ဥပဒေနှင့် လိုက်နာမှု စံနှုန်းများ (Compliance):** ISO 27001, SOC2, PCI-DSS စသည့် နိုင်ငံတကာ အသိအမှတ်ပြု လက်မှတ်များ ရရှိရန်အတွက် Audit Log အပြည့်အစုံ ပြသနိုင်ရပါမည်။

### (ဂ) AWS တွင် မရှိမဖြစ် Audit ဝန်ဆောင်မှု နှစ်ခု

```
┌────────────────────────────────────────────────────────┐
│                   AWS Audit စနစ်                        │
├───────────────────────────┬────────────────────────────┤
│     AWS CloudTrail        │        AWS Config          │
├───────────────────────────┼────────────────────────────┤
│ • API Calls အားလုံးကို      │ • Resource Configurations  │
│   မှတ်တမ်းတင်သည် (Who/What)│   များ မည်သို့ ပြောင်းလဲခဲ့သည်ကို│
│ • ဥပမာ: "kyaw-dev က      │   စောင့်ကြည့်သည် (State Audit)│
│   Security Group ကို      │ • ဥပမာ: "Port 22 ပွင့်သွားသော│
│   ပြင်ဆင်လိုက်သည်"         │   Security Group များကို      │
│                           │   Non-compliant ဟု သတ်မှတ်သည်" │
└───────────────────────────┴────────────────────────────┘
```

## အနှစ်ချုပ် လေ့လာမှုမှတ်စု (Operations Checklist)
| ဝေါဟာရ | လုပ်ဆောင်ချက် အနှစ်ချုပ် | AWS မရှိမဖြစ် Service |
| :--- | :--- | :--- |
| **Logging** | အမှားနှင့် ဖြစ်ရပ်များကို စာအုပ်ထဲတွင် မှတ်တမ်းတင်ခြင်း | CloudWatch Logs / VPC Flow Logs |
| **Monitoring** | စနစ်ကျန်းမာရေးကို သာမိုမီတာဖြင့် တိုင်းတာ သတိပေးခြင်း | CloudWatch Metrics & Alarms |
| **Backup** | ဒေတာမပျောက်ပျက်စေရန် အရန်မိတ္တူ ကူးထားခြင်း | AWS Backup / RDS Automated Snapshot |
| **Audit** | မည်သူက မည်သည့်အရာကို ပြုပြင်ပြောင်းလဲခဲ့သည်ကို စစ်ဆေးခြင်း | AWS CloudTrail / AWS Config |
