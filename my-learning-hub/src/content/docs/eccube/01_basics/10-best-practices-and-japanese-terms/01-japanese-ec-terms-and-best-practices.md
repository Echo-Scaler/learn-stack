## Module 10: ဂျပန် E-Commerce အသုံးအနှုန်းများ (Glossary) နှင့် Best Practices

ဂျပန် IT ကုမ္ပဏီများနှင့် Project များတွင် EC-CUBE ရေးသားရာတွင် မဖြစ်မနေ သိထားရမည့် **ဂျပန် E-Commerce အသုံးအနှုန်းပေါင်း ၁၀၀ ကျော် (Terminology Glossary)** နှင့် **လိုက်နာရမည့် အလေ့အကျင့်ကောင်းများ (Best Practices)** ကို စုစည်းဖော်ပြထားပါသည်။

## ၂။ EC-CUBE Development Best Practices (လိုက်နာရမည့် အလေ့အကျင့်ကောင်းများ)

### ✅ လိုက်နာရမည့် အချက်များ (DO's):
1. **Always Use `app/Customize`**: Custom Logic အားလုံးကို `app/Customize/` အောက်တွင်သာ ရေးသားပါ။
2. **Use Traits for Entity Extension**: Column အသစ်ထည့်လိုပါက `ProductTrait.php` စသည့် Trait ကိုသာ သုံးပါ။
3. **Use Event Subscribers**: မူရင်း Process များတွင် ကြားဖြတ် Logic ထည့်လိုပါက Event System / Hook Points ကို အသုံးပြုပါ။
4. **Use Migrations in Git**: Database အပြောင်းအလဲများကို Doctrine Migration ဖိုင်များဖြင့် Team အချင်းချင်း Track လုပ်ပါ။
5. **Clear Cache on Changes**: Config သို့မဟုတ် Code ပြောင်းပြီးပါက `bin/console cache:clear` ပြုလုပ်ရန် မမေ့ပါနှင့်။
6. **Set Strict Types in PHP 8**: Type Safety ရှိစေရန် `declare(strict_types=1);` ကို အသုံးပြုပါ။

---

### ❌ ရှောင်ကြဉ်ရမည့် အချက်များ (DON'Ts):
1. **NEVER modify `src/Eccube`**: Core Folder ထဲရှိ ဖိုင်များကို မည်သည့်အခါမှ တိုက်ရိုက် မပြင်ပါနှင့်။
2. **Never hardcode Credentials**: Database Passwords, API Keys များကို Code ထဲတွင် မရေးဘဲ `.env` တွင်သာ ထားပါ။
3. **Never store Credit Card details in Database**: Security နှင့် PCI-DSS စည်းမျဉ်းအရ Card Number / CVV များကို Database ထဲတွင် လုံးဝ မသိမ်းဆည်းရပါ။ Payment Gateway Tokenization ကိုသာ သုံးပါ။
4. **Never commit runtime folders**: `var/cache/`, `var/log/`, `html/upload/` များကို Git Repo ထဲသို့ Commit မလုပ်ပါနှင့် (`.gitignore` တွင် ထည့်ထားပါ)။

## ၃။ သင်ရိုး ပြီးဆုံးခြင်းနှင့် ရှေ့ဆက် လေ့လာရမည့် လမ်းညွှန် (Course Completion & Next Steps)

ဂုဏ်ယူပါသည်! 🎉 သင်သည် EC-CUBE 4.x ၏ အခြေခံမှစ၍ အဆင့်မြင့် Customization နှင့် Plugin Development အထိ မြန်မာဘာသာဖြင့် စနစ်တကျ လေ့လာပြီးမြောက်ခဲ့ပြီ ဖြစ်ပါသည်။

### ရှေ့ဆက် လက်တွေ့ လေ့ကျင့်ရန် အကြံပြုချက်များ:
1. Local Docker ပေါ်တွင် လက်တွေ့ ဆိုင်တစ်ဆိုင် တည်ဆောက်ပြီး မိမိကိုယ်ပိုင် ဒီဇိုင်း Theme ပြင်ဆင်ကြည့်ပါ။
2. External API (ဥပမာ: Telegram / Discord Bot သို့မဟုတ် Point System) ဖြင့် ချိတ်ဆက်သော Plugin တစ်ခု ရေးသားစမ်းသပ်ပါ။
3. ဂျပန် E-Commerce Project များတွင် တာဝန်ယူ ရေးသားသည့်အခါ ဤသင်ရိုးရှိ စကားလုံးများနှင့် Code Snippet များကို Reference အဖြစ် ပြန်လည် ကြည့်ရှုအသုံးချနိုင်ပါသည်။
